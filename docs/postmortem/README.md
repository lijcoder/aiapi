# 事故复盘

> 记录**已经发生**的故障：机制、为什么所有安全网都没拦住、加了什么护栏。
> 与[决策记录](../decisions/README.md)的区别：决策是"主动这么定"，复盘是"被动发生了"。

## 什么时候写

同时满足三条才写（否则修完就算）：

- **机制不显然**：根因不是打错字，而是需要想一遍才能理解的行为
- **系统性逃逸**：没被拦住的原因是测试/工具/约定上的缺口，不是运气差
- **重现成本高**：当时花了不少时间定位，换个人还会再花一遍

## 结构

```markdown
# <一句话：什么坏了>

- **日期**：YYYY-MM-DD
- **影响**：谁受影响、范围多大、持续多久
- **状态**：已修复 / 已缓解

## 概要
30 秒能读完：什么坏了、根因、为什么逃逸、长期教训。

## 时间线
发现 → 定位 → 修复的关键节点（只记证据，不写成教程）。

## 根因
机制层面的原因，链接到代码。

## 为什么没被拦住
逐个检查每道安全网（测试、门禁、文档、review）为什么失效。**这一节决定复盘的价值。**

## 护栏
把教训固化成可执行的东西：新增的测试、门禁、规则。每条都要能被后来者验证。
```

## 维护

- 护栏必须落地成**测试或门禁**才算完成；只写一句"以后注意"不算。
- 复盘描述当前状态与机制，不写成教学叙事；细节以链接代替复制。
