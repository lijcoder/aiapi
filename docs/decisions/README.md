# 决策记录

> 记录**为什么这么定**：背景、决定、被否决的方案、代价。代码和文档只能说明"是什么"，说明不了"为什么不那样"。
> 操作步骤不放这里（→ 包级 `AGENTS.md`）；已发生的变化不放这里（→ [`../../CHANGELOG.md`](../../CHANGELOG.md)）。

## 什么时候写

满足任一条就写：

- 有**反直觉**的选择（后人看代码会想"为什么不直接用 X"）
- 有两个以上**看起来都合理**的方案，需要一个理由把后来者按住
- 决定带来**长期约束**（兼容性、性能、安全边界）
- 当时**故意不做**某件事（避免后人重复论证）

日常改动、纯机械重构、只影响一个函数的实现细节都不写。

## 格式

文件名 `YYYY-MM-DD-主题.md`（主题用连字符，小写英文或中文均可）：

```markdown
# <一句话结论>

- **状态**：已实施 / 进行中 / 已否决
- **日期**：YYYY-MM-DD
- **相关**：<代码与文档的相对链接>

## 背景
当时面对什么问题，有哪些约束。

## 决定
做了什么，关键实现落在哪里（链接到文件与行）。

## 否决的方案
考虑过但没选的方案，以及否决理由——**这一节最重要**，它防止后人重新论证。

## 代价与后果
这个决定带来的限制、后续要遵守的规则、什么情况下应该重新评估。
```

## 维护

- 决策记录描述**决策**，不描述代码路径的现状：代码改名/移动时同步更新里面的链接与名字，但**不改决策本身**。
- 决策被推翻时**新写一篇**，在原文加一行 `- **已被 <新文件> 取代**`，不要就地改写历史。
- 不建集中索引：目录排序 + 全文搜索即可。
